# Fleet agent operation contracts

Research date: 2026-09-26. Source inspection only; no deployment or mutation tests were run for this note. Scope is traditional Kibana, pinned to the v9.5.4 bundle in [coverage/upstream.json](../coverage/upstream.json), with a structural comparison against v9.4.7. These findings do not certify either deployment version.

Primary snapshots: [v9.5.4 OpenAPI](https://github.com/elastic/kibana/blob/v9.5.4/oas_docs/output/kibana.yaml), SHA-256 `a5dd0f2a0fa30f2bdcba6b42c712b9bfcd89f22aef29c9bf5285328f014279d9`; [v9.4.7 OpenAPI](https://github.com/elastic/kibana/blob/v9.4.7/oas_docs/output/kibana.yaml), SHA-256 `4746196c160554bc3dac4800d0f19f4848b660ad8a4f1b1be7c0eef55299d660`. Pinned server sources below resolve several inaccurate generated response schemas. Those source files carry Elastic License 2.0 headers; this note summarizes behavior without copying their implementation.

## Verified request and response facts

Paths below are relative to `/api/fleet`. Mutations require `kbn-xsrf`. Parameter casing is significant. The [agent route registrations](https://github.com/elastic/kibana/blob/v9.5.4/x-pack/platform/plugins/shared/fleet/server/routes/agent/index.ts) register the scoped operations at public API version v1. This is separate from the Stack version.

| Operation | Request and response details |
| --- | --- |
| `GET /enrollment_api_keys` | Optional `page=1`, `perPage=20`, `kuery`. Response contains `items`, deprecated duplicate `list`, `total`, `page`, `perPage`. |
| `POST /enrollment_api_keys` | Required `policy_id`; optional `name`, `expiration` duration string, maximum 20 characters, such as `30d`. Omitting expiration means no expiry. Returns `{item, action:"created"}`. |
| `GET /enrollment_api_keys/{keyId}` | Runtime returns `{item}`. The generated shared schema incorrectly also requires `action:"created"`. |
| `DELETE /enrollment_api_keys/{keyId}` | Optional `forceDelete=false` invalidates the key and marks the token inactive; `true` additionally deletes its document. `includeHidden=false` controls hidden managed/agentless tokens. Returns `{action:"deleted"}` even for deactivation. Runtime can return 404 or 500. |
| `POST /agents/bulk_reassign` | Required `agents`, `policy_id`; optional `includeInactive=false`, `batchSize`, `dryRun`. |
| `POST /agents/bulk_unenroll` | Required `agents`; optional `includeInactive`, `force`, `revoke`, `batchSize`, `dryRun`. `force` bypasses hosted-agent/eligibility restrictions; `revoke` invalidates agent credentials and marks agents inactive without waiting for their ordinary unenrollment acknowledgment. These are different switches. |
| `POST /agents/bulk_update_agent_tags` | Required `agents`; optional `tagsToAdd`, `tagsToRemove`, each at most 10 strings, `includeInactive=false`, `batchSize`, `dryRun`. |
| `POST /agents/{agentId}/upgrade` | Required `version`; optional `force`, `source_uri`, `skipRateLimitCheck`. Returns `{}`, without an action ID. |
| `POST /agents/bulk_upgrade` | Required `agents`, `version`; optional `force`, `includeInactive=false`, `source_uri`, `skipRateLimitCheck`, `start_time`, `rollout_duration_seconds` with minimum 600, `batchSize`, `dryRun`. |
| `POST /agents/{agentId}/request_diagnostics` | Body may be omitted/null; optional `additional_metrics:["CPU"]`, at most one entry. Runtime returns `{actionId}`. The shared schema also permits `{count}`, although this single-agent request has no `dryRun` option. |
| `POST /agents/bulk_request_diagnostics` | Required `agents`; optional `additional_metrics:["CPU"]`, `batchSize`, `dryRun`. No `includeInactive` parameter. |

Every bulk request above accepts `agents` as either an explicit string array, maximum 10,000 IDs, or a KQL string. An empty query can select all agents. The success response is `{actionId:string}` or, with `dryRun`, `{count:number}`. It is not an inline per-agent result list. In the inspected handlers, `includeInactive` affects query selection; explicit IDs take a separate lookup path. Dry runs count selected records before some eligibility checks, so a positive count does not prove that execution will succeed. [Bulk reassign implementation](https://github.com/elastic/kibana/blob/v9.5.4/x-pack/platform/plugins/shared/fleet/server/services/agents/reassign.ts), [diagnostics implementation](https://github.com/elastic/kibana/blob/v9.5.4/x-pack/platform/plugins/shared/fleet/server/services/agents/request_diagnostics.ts).

An enrollment key object contains `id`, `api_key_id`, plaintext `api_key`, `active`, `created_at`, with optional `policy_id`, `name`, `expire_at`, `hidden`. The create handler checks that the policy exists in the current space. Treat returned credentials as secrets, including in Rust `Debug` output. Use the runtime envelope for GET rather than requiring the inaccurate `action` field. [Enrollment handlers](https://github.com/elastic/kibana/blob/v9.5.4/x-pack/platform/plugins/shared/fleet/server/routes/enrollment_api_key/handler.ts), [unenrollment implementation](https://github.com/elastic/kibana/blob/v9.5.4/x-pack/platform/plugins/shared/fleet/server/services/agents/unenroll.ts).

## Action completion and partial failure

`GET /agents/action_status` accepts `page=0`, `perPage=20`, `date` meaning created before this date, `latest` meaning latest N actions, and `errorSize=5`. It returns `{items:[...]}`, without a total/page envelope or an action-ID filter. Match the returned ID while paging/polling. Required fields include `actionId`, `type`, `status`, `creationTime`, `nbAgentsActionCreated`, `nbAgentsActioned`, `nbAgentsAck`, `nbAgentsFailed`. Optional fields include completion/cancellation/expiry times, policy/version/rollout information and `latestErrors` entries containing `agentId`, `error`, `timestamp`, and optional `hostname`.

Statuses are `COMPLETE`, `EXPIRED`, `CANCELLED`, `FAILED`, `IN_PROGRESS`, `ROLLOUT_PASSED`. The implementation counts failed responses separately from successful acknowledgments. When all targets have responded, any failures produce `FAILED`; partial failures can already be present while status remains `IN_PROGRESS`. `latestErrors` is a bounded sample, not the complete failure set. Cancellation takes precedence. Bulk work can be queued through Task Manager before agent execution begins. HTTP 200 and an action ID therefore mean acceptance, not completion. [Status calculation](https://github.com/elastic/kibana/blob/v9.5.4/x-pack/platform/plugins/shared/fleet/server/services/agents/action_status.ts), [asynchronous runner](https://github.com/elastic/kibana/blob/v9.5.4/x-pack/platform/plugins/shared/fleet/server/services/agents/action_runner.ts).

`POST /agents/actions/{actionId}/cancel` has no body and returns `{item}`. Runtime `item` contains `id`, `type:"CANCEL"`, `created_at`; generated schema-required `data` and `ack_data` are absent. The returned ID identifies the cancellation action, not the original action. The implementation only processes `UPGRADE` and `UNENROLL` actions, so this is not generic cancellation for reassignments, tags or diagnostics. A found but unsupported action can yield a cancellation-shaped response without cancelling it. Cancellation is not rollback. [Cancellation implementation](https://github.com/elastic/kibana/blob/v9.5.4/x-pack/platform/plugins/shared/fleet/server/services/agents/actions.ts#L387).

## Diagnostics files

`GET /agents/{agentId}/uploads` returns `{items}` with `id`, `name`, `filePath`, `createTime`, `status`, `actionId`, and optional `error`. Status values are `READY`, `AWAITING_UPLOAD`, `DELETED`, `EXPIRED`, `IN_PROGRESS`, `FAILED`. Before upload metadata exists, `id` can be the action ID and `filePath` can be empty. Wait for `READY` and correlate `actionId` before downloading.

The download route is `GET /agents/files/{fileId}/{fileName}`. Runtime streams `application/octet-stream` with attachment headers; the generated OpenAPI incorrectly describes an `application/json` object. Handle bytes/streaming and preserve normal JSON HTTP-error handling. Encode each path segment; do not interpret the returned `filePath` as a local filesystem path. Optional cleanup route `DELETE /agents/files/{fileId}` returns `{id,deleted}`. Deleted files are omitted from later upload lists. [Upload implementation](https://github.com/elastic/kibana/blob/v9.5.4/x-pack/platform/plugins/shared/fleet/server/services/agents/uploads.ts).

Remote diagnostics require an online Healthy or Unhealthy agent. The normal retention period is seven days, and archive format can change. Redaction is incomplete, so diagnostics are private test artifacts, not committed fixtures. [Diagnostics documentation](https://www.elastic.co/docs/troubleshoot/ingest/fleet/diagnostics).

## Version, privilege and deployment limits

- Every scoped route exists in both inspected snapshots. The v9.5.4 enrollment-delete schema adds `forceDelete`/`includeHidden`; omit these options for the v9.4.7 baseline unless runtime tests establish support. Both snapshots already support key expiration. The extra enrollment `_bulk_delete` route appears only in v9.5.4 and is outside this implementation scope.
- The action-type enum adds `REMOVE_COLLECTOR` in v9.5.4. Preserve unknown action/status strings for forward compatibility. Other compared differences are explicit nullable/default annotations; file-route success contracts are unchanged, including the inaccurate download schema. This comparison is not runtime compatibility evidence.
- Diagnostics requests, status and upload reads/downloads require Fleet agent READ privileges. Agent changes/cancellation/file deletion require ALL. Enrollment-key permissions are separately registered. Test restricted identities explicitly. [Agent routes](https://github.com/elastic/kibana/blob/v9.5.4/x-pack/platform/plugins/shared/fleet/server/routes/agent/index.ts), [enrollment routes](https://github.com/elastic/kibana/blob/v9.5.4/x-pack/platform/plugins/shared/fleet/server/routes/enrollment_api_key/index.ts).
- Elastic documents subscription limits for bulk selection and scheduled binary upgrades. The inspected handlers do not establish a complete Basic-license entitlement contract. Record the actual license and observed supported behavior; do not advertise every bulk/scheduled capability as Basic merely because a handler lacks an obvious license check. Keep paid-feature tests in an explicitly licensed profile. [Fleet overview](https://www.elastic.co/docs/reference/fleet), [upgrade feature limits](https://www.elastic.co/docs/reference/fleet/upgrade-elastic-agent).
- Fleet cannot upgrade Docker/Kubernetes agents or Linux DEB/RPM installations. Linux tarball installations running as a service support it. Agent target minor versions cannot exceed Fleet Server's minor version; patch differences are allowed. The single-upgrade handler can reject ineligible/unenrolling agents with 400 and recently upgraded agents with 429 plus `Retry-After`. Do not use `force`/`skipRateLimitCheck` to disguise an unsupported test environment. [Upgrade restrictions](https://www.elastic.co/docs/reference/fleet/upgrade-elastic-agent), [pinned handler](https://github.com/elastic/kibana/blob/v9.5.4/x-pack/platform/plugins/shared/fleet/server/routes/agent/upgrade_handler.ts).

## Recommended deterministic tests

1. In the existing disposable Basic/container profile, create two ordinary policies and two real agents with a run-specific tag. Exercise enrollment-key list/create/get/revoke with bounded expiry, assert deactivation, and never log the credential. Use explicit IDs and a run-specific KQL filter; verify unselected agents remain unchanged.
2. Cover both bulk response variants. For tags/reassignment, poll independent agent reads and policy acknowledgment as well as action status. Set `batchSize=1` with a two-agent KQL selection to exercise queued batching. Make one agent already assigned to the destination and the other eligible: pinned reassign code records the first as an error and processes the second, providing a deterministic partial-failure case. [Reassign batch checks](https://github.com/elastic/kibana/blob/v9.5.4/x-pack/platform/plugins/shared/fleet/server/services/agents/reassign_action_runner.ts).
3. Request diagnostics without CPU profiling first. Poll the matching upload until `READY`, download through the crate, verify a nonempty ZIP, then remove it. Do not snapshot timestamps, UUIDs or archive bytes. Exercise single and bulk requests separately. Unenroll last, then verify inactive state and cleanup.
4. Use an isolated VM with a real tarball-installed service agent for successful single/bulk upgrade and cancellation. Pin both starting/target artifacts and their checksums. Give cancellation a future scheduled upgrade in the licensed profile and poll the original action's cancellation state; avoid racing an immediate upgrade. Container rejection, upgrade dry runs and transport mocks do not certify successful upgrades.
5. Gate each claimed operation on its recorded outcome: successful state transition, intentional negative case, skipped, or not applicable. Test both exact Stack baselines with restricted credentials. Preserve first failure, status counters and redacted logs on timeout; retry bounded reads, not uncertain mutations. No release claim for an unexecuted VM or paid-feature profile.
